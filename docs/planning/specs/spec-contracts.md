### 3.3.2 Ethplane.sol — the consolidated contract spec (rewritten in full 2026-09-08 after contract-spec-audit.md; §3.13.2, §3.14, §3.21 and §3.22.2 are now history for this section, this text wins)
One contract holds registry, leases, submissions, measurements, head, escrow and attribution credits. EthplaneHead is folded in (head lives here, so verifier rotation cannot strand it). OpenZeppelin 5: `ReentrancyGuard`, `EIP712`, `ECDSA`, `SafeERC20`. Metric values are raw integers (cycles); no scaling.

Storage:
```solidity
enum Status { PENDING, FAIL, PASS, REVIEW }   // PENDING = submitted, not yet measured; FAIL is final
enum Kind { WINNER, PARENT, VERIFIER, COMPUTE, REGISTRANT }   // attribution kinds paid; REVIEWED rows are events only
struct Node {
  address registrant;        // ENS subname owner at defineNode (maintainer of this node; sets verifier, closes, confirms reviews)
  address verifier;          // measurement signer for this node; zero = "registered, no verifier": cannot be claimed
  address reviewer;          // decides REVIEW verdicts; must differ from registrant and verifier (default: the global maintainer)
  bytes32 criterionHash; uint8 lane; address assignee;          // lane 0 open (claim alongside), 1 preassigned
  uint64 leaseDuration; uint64 heartbeatEvery;
  Split split;               // struct Split { uint16 winnerBps; uint16 parentBps; uint16 verifierBps; uint16 computeBps; uint16 registrantBps; } sum == 10000 (checked). A struct, not uint16[5]: Privy's policy engine addresses struct members (defineNode.split.verifierBps) but never array elements (P6b).
  uint16 targetGainBps; uint16 thresholdBps;                     // thresholdBps 0 = strict reduction
  uint16 paidGainBps;        // cumulative gain already paid, measured from originalMetric
  uint256 originalMetric;    // immutable after recordBaseline (denominator of cumulative gain)
  uint256 bestMetric;        // the frontier; only ever decreases; gates PASS and drives head
  uint256 baseProvingMicros; uint256 baseProofBytes; uint256 baseVerifyMicros; uint16 spreadBps;  // non-regression bounds
  uint256 bounty;            // total funded
  uint256 released;          // total credited out
  bytes32 head;              // artifact hash at the frontier
  uint256 leaseSeq; bool open; bool closed;
}
struct Lease  { address lineage; address operator; uint64 start; uint64 expiry; uint64 lastHeartbeat; bytes32 fromHash; uint256 seq; bool active; }
struct Submission { bytes32 nodeId; address lineage; address operator; uint256 leaseSeq; bytes32[] parents; Status status; uint256 cycles; }
mapping(bytes32 => Node) public nodes;
mapping(bytes32 => Lease) public leases;                        // key keccak256(abi.encode(nodeId, lineage)); fixed-length operands, no collision
mapping(bytes32 => mapping(address => uint64)) public cooldownUntil;   // nodeId -> operator
mapping(address => address) public lineageOperator;             // lineage key -> operator wallet (set once, operator-accepted)
mapping(address => address) public pendingOperator;             // lineage key -> operator proposed, awaiting acceptLineage
mapping(address => bytes32) public lineageGroup;                // lineage key -> ENS group name hash
mapping(bytes32 => Submission) public submissions;              // artifactHash -> submission
mapping(bytes32 => mapping(address => uint256)) public funded;  // nodeId -> funder -> amount
mapping(bytes32 => mapping(address => bool)) public unusedWithdrawn;
mapping(address => uint256) public owed;                        // pull-based payouts
mapping(address => uint256) public nonces;                      // EIP-712 relay nonces per guest wallet
mapping(address => bool) public relays;
address public immutable maintainer; IERC20 public immutable plane; bytes32[] public strawmapIds; mapping(bytes32 => bool) public isStrawmapId;
```
Rules and functions (every state change emits; names final; a cold agent implements exactly these):
- **Registration, two-step so nobody can bind a key they do not hold or an operator that did not agree.** `registerLineage(address operator, bytes32 groupName)` by the lineage key itself (msg.sender is the lineage; require `lineageOperator[msg.sender] == 0`): stores `pendingOperator[msg.sender] = operator`; emits `LineageProposed(lineage, operator, groupName)`. `acceptLineage(address lineage)` by the operator: require `pendingOperator[lineage] == msg.sender`; sets `lineageOperator[lineage] = msg.sender`; emits `LineageRegistered(lineage, operator, groupName)`. Guests: `registerLineageFor(guest, sig)` through the relay binds the guest wallet as its own lineage and operator in one step (the signature is the acceptance).
- **defineNode(nodeId, criterionHash, lane, assignee, leaseDuration, heartbeatEvery, Split split, targetGainBps, thresholdBps)**: require `isStrawmapId[nodeId]`; require `nodes[nodeId].registrant == 0`; require `IRegistry(ethplaneSubregistry).ownerOf(tokenIdOf(label)) == msg.sender` (the ENSv2 subregistry's token owner, not the resolver's `addr`, which is where a name points and is owner-settable; `tokenIdOf` per contracts-v2 `PermissionedRegistry`, the same value `ens whois` prints; for ids not yet registered as names the maintainer defines with itself as registrant); require the five fields sum to 10000, `split.verifierBps >= 1000`, `split.parentBps >= 1000` (verifier and reused-parent floors are contract law; the Privy policy mirrors the verifier floor as `defineNode.split.verifierBps gte 1000`); stores registrant = msg.sender and `reviewer = maintainer` (registrant may later `setReviewer` to any address that is neither registrant nor verifier); emits `NodeDefined(nodeId, registrant, criterionHash, lane, leaseDuration, heartbeatEvery, split, targetGainBps, thresholdBps)`.
- **setNodeVerifier(nodeId, verifier)** by registrant: allowed while no lease is active; emits `VerifierSet(nodeId, verifier)`. Measurements are keyed by leaseSeq and carry the signer in the event, so history survives rotation.
- **fundNode(nodeId, amount)** by anyone, `nonReentrant`: require `!closed`; `plane.safeTransferFrom(msg.sender, this, amount)`; `funded[nodeId][msg.sender] += amount; bounty += amount; open = true` (node must have a verifier and a baseline before claims, see below); emits `NodeFunded(nodeId, funder, amount, bounty)`. Multiple funders add; nothing is overwritten.
- **recordBaseline(nodeId, cycles, provingMicros, proofBytes, verifyMicros, spreadBps)** by node verifier, **once**: require `originalMetric == 0`; sets originalMetric = bestMetric = cycles and the non-regression bounds; emits `BaselineRecorded(...)`. Claims require `originalMetric != 0 && verifier != 0 && open && !closed`.
- **claim(nodeId, fromHash)** by a registered lineage key: operator = `lineageOperator[msg.sender]` (require set); lane 0 or msg.sender == assignee; `cooldownUntil[nodeId][operator] <= now`; require no active lease for this lineage on this node; require `fromHash == 0 || submissions[fromHash].nodeId == nodeId` (a claim may start from ANY known submission on the node, verified or not: the recovery beat starts from the killed lineage's last, unverified artifact; bounded to real submissions, never arbitrary bytes); writes `leases[key]`, `leaseSeq++`, `seq = leaseSeq`; emits `LeaseClaimed(nodeId, lineage, operator, fromHash, expiry, seq)`.
- **heartbeat(nodeId)** by the lease holder: require active and `now <= lastHeartbeat + heartbeatEvery`; emits `Heartbeat(nodeId, lineage, seq, now)`.
- **forfeit(nodeId, lineage)** by anyone: require active and (`now > expiry` or `now > lastHeartbeat + heartbeatEvery`); `active = false`; `cooldownUntil[nodeId][operator] = now + leaseDuration`; emits `LeaseForfeited(nodeId, lineage, operator, seq, reason)` (1 expiry, 2 heartbeat). Safe to be permissionless: it only fires on a genuinely missed heartbeat or expiry.
- **submit(nodeId, artifactHash, parents)** by the lease holder: require `parents.length <= 8`; each parent must be a known submission on this node (any status: the reuse edge is recorded whether or not the parent was verified; only PASS parents are paid, below); require `submissions[artifactHash].lineage == 0`; stores Submission{…, parents, PENDING, 0}; emits `SubmissionMade(nodeId, lineage, operator, artifactHash, seq, parents)`.
- **recordMeasurement(nodeId, artifactHash, cycles, provingMicros, proofBytes, verifyMicros, bool verifierAccepted, bytes32 evidenceHash)** by node verifier: require submission exists and its status is PENDING — exactly one measurement per artifact, a FAIL is final (a non-deterministic provingMicros can never be re-rolled into a PASS); the contract decides:
  `improved = verifierAccepted && cycles < bestMetric && (bestMetric - cycles) * 10000 / bestMetric >= thresholdBps && provingMicros <= baseProvingMicros * (10000 + spreadBps) / 10000 && proofBytes <= baseProofBytes && verifyMicros <= baseVerifyMicros * 10500 / 10000`;
  `dropBps = improved ? (bestMetric - cycles) * 10000 / bestMetric : 0`;
  status = !improved ? FAIL : (dropBps > 2000 ? REVIEW : PASS). Stores cycles and status; emits `MeasurementRecorded(nodeId, artifactHash, seq, cycles, provingMicros, proofBytes, verifyMicros, verifierAccepted, status, evidenceHash, msg.sender)`. On PASS: `_advance(nodeId, artifactHash, cycles)`.
- **confirmReview(nodeId, artifactHash, bool pass)** by `node.reviewer` (never the registrant or the verifier, both of whom are paid by the outcome; the reviewer earns the `reviewed` row and no tokens; through the relay with a signature when the reviewer is a guest): require status REVIEW; pass → status PASS and `_advance`; fail → FAIL; emits `ReviewConfirmed(nodeId, artifactHash, reviewer, pass)` — the human "reviewed" attribution row is this event (amount 0).
- **_advance(nodeId, artifactHash, cycles)**: `bestMetric = cycles; head = artifactHash`; emits `HeadAdvanced(nodeId, artifactHash, cycles)`; then `_release(nodeId, artifactHash)`.
- **_release(nodeId, artifactHash)** — no external calls, credits only:
  `cumulativeGainBps = (originalMetric - bestMetric) * 10000 / originalMetric; capped = min(cumulativeGainBps, targetGainBps); if (capped <= paidGainBps) return; payout = bounty * (capped - paidGainBps) / targetGainBps; payout = min(payout, bounty - released); paidGainBps = capped; released += payout;`
  shares = payout × split.<kind>Bps / 10000 each. WINNER → `owed[submission.operator]`; PARENT → split equally among the distinct operators of those `submission.parents` whose status is PASS and whose operator differs from the winner's (unverified parents are recorded as reuse edges but not paid; skipped shares stay in escrow); VERIFIER → `owed[node.verifier]`; COMPUTE → stays in escrow in v1 (emitted as `Payout(..., COMPUTE, amount)` to address(0) so the indexer shows it); REGISTRANT → `owed[node.registrant]`. Integer division remainders stay in escrow. Emits `Payout(nodeId, artifactHash, to, kind, amount)` per credit. Invariant tested: N micro-passes credit exactly what one combined pass credits.
- **withdraw()** `nonReentrant`: `amount = owed[msg.sender]; owed = 0; plane.safeTransfer(msg.sender, amount)`; emits `Withdrawn(to, amount)`.
- **closeNode(nodeId)** by registrant: require no active lease; `closed = true; open = false`; emits `NodeClosed`. **withdrawUnused(nodeId)** by any funder after close, `nonReentrant`: `remaining = bounty - released; share = remaining * funded[nodeId][msg.sender] / bounty`; once per funder; emits `UnusedWithdrawn(nodeId, funder, share)`. Funders get back their pro-rata share, never someone else's.
- **Relay (guests).** `claimFor(nodeId, guest, fromHash, nonce, deadline, sig)`, `submitFor(nodeId, guest, artifactHash, parents, nonce, deadline, sig)`, `registerLineageFor(guest, groupName, nonce, deadline, sig)`, `confirmReviewFor(...)`: `require(relays[msg.sender]); require(now <= deadline); require(nonce == nonces[guest]++)`; EIP-712 domain `("Ethplane","1",chainId,address(this))`, typed structs with the exact field lists above; signer recovered must equal `guest`; then the same internal path as the direct call with `lineage = guest`. Guests are their own operator; a forfeited guest can evade cooldown by logging in with a new email (new wallet). Accepted for the hackathon and stated in README limitations with the correct reason: evasion buys no exclusivity (claim-alongside blocks nobody) and no money (payout is cumulative and capped); what it buys is extra submissions, each costing the verifier one measurement, and that is bounded by the relay's rate limit (6 per minute per guest, 3.6) rather than by the contract.
- **Admin:** `setRelay(address, bool)` by maintainer; `seedStrawmap(bytes32[] ids)` once by maintainer (the 65 ids). No other maintainer power over nodes; no pausable; no upgradeability.
- **Attribution rows for the indexer** are exactly the events `Payout` (kinds 0–4), `MeasurementRecorded` (verification work by the verifier), `SubmissionMade` with parents (reuse edges), `ReviewConfirmed` (human review), `NodeDefined` (registration). The SQLite schema in 3.6 has one table per event; nothing is inferred.

### 3.13.2 Contract corrections (Ethplane.sol)
- **Leases** are keyed by `leaseKey = keccak256(abi.encodePacked(nodeId, lineage))` everywhere; `Node.activeLeases` counts them; the claim guard is `!leases[leaseKey].active`; `forfeit(nodeId, lineage)` and `heartbeat(nodeId)` use the same key; the storage line `mapping(bytes32 => Lease) leases; // nodeId -> current lease` is replaced by `// leaseKey -> lease`.
- **Parents** are stored as `mapping(bytes32 => bytes32[]) parentsOf` and `mapping(bytes32 => address) submitterOf`, so `_release` can enumerate parents and pay `operatorOf[submitterOf[parent]]`.
- **Baseline before any verdict.** `recordBaseline(bytes32 nodeId, uint256 metricMicros, uint16 spreadBps)` onlyVerifier sets both `originalMetric` (immutable; the denominator of cumulative gain) and `bestMetric` (the frontier; gates `passed` and drives head, only ever decreases) to `metric`, and records `spreadBps` for the non-regression fields only; `thresholdBps` is a defineNode parameter (0 for the PoC node, 3.22.1) and is not derived from spread, because the cycles metric has none; `recordVerdict` reverts with `NoBaseline` if `bestMetric == 0`. The first improvement is measured against the unmodified build, as the criterion says.
- **Integer maths, basis points.** `gainBps = (bestMetric - metric) * 10000 / bestMetric` (only evaluated when `metric < bestMetric`, so no underflow); passed requires `metric < bestMetric && gainBps >= thresholdBps` (thresholdBps is 0 for the PoC node, 3.22.1: strict reduction); payout is against cumulative progress from the ORIGINAL baseline (critic, 16:45: a per-submission payout with any floor can be salami-sliced): `cumulativeGainBps = (originalMetric - metric) * 10000 / originalMetric`; `payout = bounty * (min(cumulativeGainBps, targetGainBps) - paidGainBps) / targetGainBps`; then `paidGainBps = min(cumulativeGainBps, targetGainBps)`. Total payout depends only on total progress, never on how it is divided; there is no floor. A one-cycle pass therefore pays 0 PLANE but is a verified result: it advances head, earns the attribution row, and the lineage's later progress is paid from that point. The split applies `splitBps` to `payout` with integer division and the remainder returned to escrow. Worked example: bounty 10,000 PLANE, targetGainBps 1000, first pass at cumulative 3 % → payout 3,000; winner 2,040, parents 450, verifier 300, compute 150 to escrow, registrant 60; a second pass reaching cumulative 5 % pays 2,000 more; ten one-cycle passes pay 0 in total.
- **Guest submissions** through `submitFor` use `submitterOf[artifactHash] = guestWallet` with `operatorOf[guestWallet] = guestWallet` set by the relay's `registerLineageFor` (relay-only, requires the guest's signature over `keccak(guestWallet, guestName)`).
- Tests added: `test_gainBpsIntegerMaths`, `test_noBaselineReverts`, `test_claimRequiresRegisteredLineage`, `test_parentsEnumeratedAndPaid`, `test_fundNodeOnlyTreasury`.

### 3.22.2 Check-skipping closed (2026-09-08 evening, critic C-4; verified in crates/rec_aggregation/src/aggregation.rs:398-406)
The aggregate's public input is `statement_digest(public_keys.len(), pubkeys_hash(public_keys), message, epoch_hash, defer)`, so the signer count and the key set are bound: a guest cannot aggregate a smaller or different set against the verifier's public input. What the digest does not bind is whether each signature was checked, so: (a) every submission runs three negative vectors at fixed positions first, last and one verifier-random index; (b) any submission that clears the threshold runs the full one-bad-signature sweep, 900 runs each with exactly one invalid signature at index i, spread over the host's cores; a guest that skips any index is caught deterministically because that index's run must fail and does not. The sweep is ~1.4 s × 900 / cores; on 26 vCPU about one minute. (c) The perf-hunt numbers of 2026-09-08 afternoon are withdrawn by the builder (one stale binary measured at every commit); the metric decision rests on cycles being deterministic by construction, not on those numbers, and reachability is open until the corrected hunt (binary sha256 printed per run) reports.
- **Refinements (critic, 2026-09-08 evening):** (d) each negative vector flips a byte at a verifier-random offset inside the signature, not a fixed offset, so a guest that verifies only part of each signature is caught; (e) the verifier records the sha256 of the binary it measured with every measurement and refuses to measure when a non-empty diff was applied but the binary hash equals the reference binary's (the stale-binary failure of the perf hunt, moved to where it could pay out). Both live in `verifier/run.py` next to the frozen-path check.

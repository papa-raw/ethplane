- Resolver on the hackathon deployment (P13b, 2026-09-08): PermissionedResolver proxy DEPLOYED through the hackathon VerifiableFactory at `0x7989BcF8BCf00A6A4C3f6280E01b53C949c9A909` (`ENS_HK_RESOLVER`; salt keccak256(abi.encode(keccak256("OwnedResolver"), admin, 0)); deployProxy with EMPTY init data: the deployed implementation has no initialize function, which is why every initialised deploy reverted). The deployed code is the name-based variant: `setText(bytes dnsName, string key, string value)`, `setData`, `setName`, `resolve(bytes,bytes)`, `grantRoles(uint256 resource, uint256 roles, address account)`; none of the `authorize*Roles` helpers exist. **Scoping, measured:** `setText` reverts with `EACUnauthorizedAccountRoles(resource, 16, caller)`, and the resource id depends on the KEY only (same key on two names → same resource; two keys on one name → different resources). A role granted for a key is a role for that key on every name the instance serves. **Decision: one resolver proxy per node name** (about 102k gas each; 65 nodes ≈ 6.7M gas, fine at Sepolia prices), never a shared one, so the verifier's role on `ethplane.head` reaches one node; operator, lineage and guest names share one separate proxy (their records are written by their owners, no cross-name verifier role). Day 1 scripts: `ens/deploy-node-resolver.ts` (deployProxy with salt = keccak256(abi.encode(keccak256("OwnedResolver"), admin, nodeIndex))), then `grantRoles(resourceOf("ethplane.head"), ROLE_SET_TEXT, verifier)` and the same for `ethplane.status`, resource id read from a dry-run revert or computed once the derivation is confirmed. Registrant-owned nodes deploy their own proxy at registration (the dashboard's Register control includes it). Open probe, being closed by the builder: the name-independence was shown with one unregistered second name; it is repeated with a registered one before §3.4 is called final.

- EAC role grant is NOT a CLI command ([private note, withheld], 2026-09-08): `ens/grant-roles.ts` calls `PermissionedResolver.authorizeTextRoles(bytes toName, string key, address account, bool grant)` (contracts-v2 `PermissionedResolver.sol:303`) on our ONE resolver proxy `0x068D54D4cA4655f3023551989925b65bC0a17A29` (a canonical `PermissionedResolverImpl` proxy; EAC resources are keyed by namehash + key, so this single instance serves every node, operator, lineage and guest name: no per-name resolver deploys, just `resolver set` to this address). The caller must hold `ROLE_SET_TEXT_ADMIN` on the name's any-key resource (the deployer does, as admin). Role constants from `PermissionedResolverLib.sol`: `ROLE_SET_TEXT = 1 << 4`, `ROLE_SET_TEXT_ADMIN = ROLE_SET_TEXT << 128` (full table in [private note, withheld]). Grants: verifier key → `authorizeTextRoles(dnsEncode(nodeName), 'ethplane.head', verifier, true)` and the same for `ethplane.status` on every node name; lineage keys → no grant; guest names → the guest wallet holds admin on its own name only.

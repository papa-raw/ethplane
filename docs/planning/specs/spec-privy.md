# Ethplane spec extract for the build swarms · from the private PRD, 2026-09-08 19:04 · private to host A, never commit this file

## 3.5 Privy (server SDK `@privy-io/server-auth@1.32.5`, type-checked in P6; React SDK `@privy-io/react-auth` latest for the web)
- Client: `const privy = new PrivyClient(process.env.PRIVY_APP_ID!, process.env.PRIVY_APP_SECRET!, { walletApi: { authorizationPrivateKey: process.env.PRIVY_AUTHORIZATION_KEY! } })`. App "EthPlane" exists (app id, secret, authorization key id + key, and PRIVY_JWKS_URL for token verification are in `.env`; verified against the API 2026-09-08). Dashboard settings confirmed from the app config 2026-09-08 17:05: embedded wallets create-on-login = users-without-wallets (Ethereum); allowed domains https://ethplane.ecofrontiers.xyz and http://localhost; login methods email + external wallet (GitHub OAuth is OFF and stays off: it needs a GitHub OAuth app, not worth the setup; the PRD's login list is email and wallet); smart wallets (Alchemy light_account) are enabled with the Pimlico public bundler on Sepolia, harmless and unused unless gas sponsorship is wired. Gas for guest transactions: guests pay their own Sepolia gas by default; the Pimlico public bundler (`PIMLICO_RPC_URL`, entry points 0.6/0.7 on Sepolia) is the sponsorship path if a guest arrives with an empty wallet, wired only if it costs under an hour.
- Treasury policy, created once by `api/src/privy.ts:createTreasuryPolicy()` — shape verified live in P6b (policy h4y52230iqevk0p8xvanzjba on the dev app; the production one is created by the runbook):
  - Rules are per RPC method: every allow-rule is written twice, once for `eth_sendTransaction` and once for `eth_signTransaction`, or signing is deny-by-default (P6b: a legal signTransaction was refused with "RPC request denied due to policy violation").
  - A function is pinned implicitly by naming one of its arguments; there is no `method` field (`field: 'method'` is refused: "must be in the format of functionName.argumentName..."). A rule cannot say "allow defineNode with no constraint", so every rule names an argument.
  - Rules (each × 2 methods): `approve-plane`: to eq PLANE_ADDRESS, calldata `approve.spender eq ETHPLANE_ADDRESS`; `fund-cap`: to eq ETHPLANE_ADDRESS, calldata `fundNode.amount lte 100000e18`; `define-floor`: to eq ETHPLANE_ADDRESS, calldata `defineNode.split.verifierBps gte 1000` (expressible because Split is a struct; array elements are not addressable, P6b). Everything else is denied by default.
  - What the policy is for: it caps money and mirrors one floor; pass/fail, the split at payout and "only after a verdict" live in the contract (3.3.2). Verified in P6b: fundNode 50000e18 signed, fundNode 200000e18 refused at signing, same wallet, same function.
- Organisation wallet: `privy.walletApi.createWallet({ chainType: 'ethereum', policyIds: [policy.id] })` bound at creation; its address is the PlaneToken `treasury` constructor arg, so **deploy order is: Privy wallet first, then PlaneToken**. Quorum (2-of-3) via `createWallet` owner/signers per the SDK types if it costs under an hour; otherwise the maintainer key is the single signer and the README says so.
- Funding a node: `privy.walletApi.ethereum.sendTransaction({ walletId, caip2: 'eip155:11155111', transaction: { to: PLANE_ADDRESS, data: approve(ETHPLANE_ADDRESS, bounty) } })` then the same with `to: ETHPLANE_ADDRESS, data: openNode(...)`. `caip2` is required and is `eip155:11155111`, not a number.
- Guests: the web app uses `PrivyProvider` (login methods email, wallet); on first login `api/src/routes/join.ts` receives the Privy access token, verifies it server-side (`privy.verifyAuthToken`), reads or creates the embedded wallet (`privy.walletApi.createWallet` for the user if none), allocates `judge-<n>`, creates the ENS subname (3.4 step 4) owned by that wallet, non-transferable, and returns `{guestName, wallet}`. Guest actions go through `relay.ts` (3.6) which submits `claimFor/submitFor` with the guest's EIP-191 signature obtained in the browser via the embedded wallet's `signMessage`.

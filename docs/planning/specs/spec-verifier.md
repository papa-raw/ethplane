- Pinned command line (from `src/main.rs`, which is outside the editable surface): `cargo run --release -- aggregate --xmss 900 --log-inv-rate 1 --repeat 3`. Metric value = cycles; `metricHash = keccak(json of all measured fields incl. binary sha256)`; the JSON is stored as `/api/artifacts/<hash>.verdict.json` and `recordMeasurement` is called with cycles, provingMicros, proofSizeBytes, verifyMicros.
- `verifier/sign.ts`: viem `writeContract` `recordMeasurement(...)` (head advances inside the contract) and the ENS `ethplane.head` record (3.4) when passed. Triggered by the API on each `SubmissionMade` event (push from the poller via a local HTTP call), never by cron.



## 3.22 Metric = cycles; one host, two lineages, two signers; edit assertion (2026-09-08 ~16:10)
> Contract clauses in this section are history: §3.3.2 (rewritten 2026-09-08) is the contract spec and wins on any conflict. Non-contract clauses here remain live.
- **Metric change.** Cycles is the right quantity for a zkVM (proving cost is a function of trace length), exact where wall time carries a ±1.9 % spread and a replay question. (The afternoon's perf-hunt numbers that first motivated the switch were withdrawn by the builder, see §3.22.2; the switch stands on these properties alone.) leanVM prints `cycles (VM steps)` (baseline 1,571,106 for the pinned command), a deterministic count: same input, same count, zero spread. Primary metric = cycles; threshold 1 % fewer (15,711 cycles) set onchain at baseline; `recordMeasurement` carries `cycles` as the metric and keeps `provingMicros`, `proofSizeBytes`, `verifyMicros` as non-regression fields (proving time may not exceed baseline mean + spread; proof size and verify time not larger). The verifier parses `cycles \(VM steps\)\s*:\s*([\d,]+)`. A cycle reduction is an algorithmic improvement by construction, which is what the roadmap node is about; the reachability pin (§3.17) is re-run against cycles (any upstream commit that reduced cycles by ≥ 1 %).
- **One host, two models, two lineages.** Default per the measured fit (30B at 0.55 ≈ 48 GiB, 7B at 0.29/16k ≈ 25.5 GiB); each lineage has its own `signer-<lineage>` user, key file, Unix socket (`/run/ethplane/signer-<lineage>.sock`) and group; the agent processes of one lineage are members of only their own group. A second host is launched only if an H100 appears, and adds nothing to the design.
- **Edit assertion.** The loop driver hashes the editable files before and after each harness call and treats "no change" as a failed attempt regardless of exit code (P9: Qwen Code exited 0 having changed nothing). Logged per attempt as `changed: false`.
- **Human contributions earn rows (critic, coverage-verdict):** two event kinds beside verified/reused/verification: `registered` (the ENS owner who registered the node earns 2 % of every release on that node; split becomes 68/15/10/5/2 bps, `Node.registrant` paid in `_release`) and `reviewed` (a human who confirms or overturns a REVIEW verdict from 3.22.1 signs `confirmReview(nodeId, artifactHash, pass)` through the relay; recorded as an attribution row with amount 0 and shown in the operator totals). Tests: `test_registrantShareOnRelease`, `test_reviewedRowRecorded`.

### 3.22.1 Criterion, final form (2026-09-08 evening, after the critic's "proof of less" objection; verified against python-verifier/verifier.py and crates/rec_aggregation)
Facts checked: the Python verifier takes bytecode, a 256-bit public input and the proof; it hard-codes the WHIR folding factors, the 17-bit query grinding and the query table, binds the bytecode hash into the Fiat–Shamir IV, and accepts an inverse rate only in 1..4 (`verifier.py:923`, `:1365-1416`). The guest is `crates/rec_aggregation/guests/aggregate.py` (a zkDSL program) compiled by `crates/lean_compiler`; cycles is the trace length of that compiled bytecode on the input, so cycles fall only when the guest or the compiler changes.
- **Editable surface:** `crates/rec_aggregation/guests/aggregate.py` and `crates/lean_compiler/`. Frozen: `crates/xmss`, `crates/sphincs`, `crates/pcs`, `crates/fiat_shamir`, `crates/primitives`, `crates/lean_vm`, `python-verifier/`, `src/main.rs`. The verifier rejects a submission whose diff touches a frozen path before measuring anything.
- **Metric:** `cycles (VM steps)` from the pinned command; pass = any strict reduction (≥ 1 cycle) below the recorded baseline, because cycles is exact and reproducible, so a one-cycle reduction is a repeatable fact and no noise margin is needed (`thresholdBps = 0`, strict less-than in the contract). Decided 2026-09-08 16:39 after the corrected reachability run: across upstream history the best cycle reduction is −0.117 % and it lives in the frozen VM; every commit touching the editable surface measured exactly 0.000 %, so a 1 % threshold had no reachable pass. The film treats an honest rejection as a decided, legitimate outcome, not a surprise. Pin: `LEANVM_COMMIT = a210ef1b` (post-rename main; the pinned command `aggregate --xmss 900 --log-inv-rate 1 --repeat 3` exists only after the rename, so commit and command are chosen together). Baseline at that commit: 1,542,812 cycles (builder's corrected harness; recorded onchain at defineNode). Non-regression: proving time ≤ baseline mean + spread, proof size and verify time not larger.
- **Statement check (closes "proof of less"):** the verifier generates its own fresh inputs with the reference build at LEANVM_COMMIT (keys, messages, 900 XMSS signatures) plus a negative set (flipped signature bytes, wrong message, wrong key); the submission's binary must produce a verifying proof on the positive set and must fail on every negative vector. Verification runs `python-verifier/verifier.py` from the reference checkout, never from the submission.
- **Review floor:** a cycle drop of more than 20 % pays nothing automatically; the verdict is recorded as REVIEW and a human confirms before release.
- **Critic clause (swarm):** reject any edit that moves computation out of the traced region or changes what the guest checks, whatever the numbers say.
- **Reachability:** the pin is re-checked against cycles; if no upstream commit reduced cycles by ≥ 1 %, the film uses the honest-rejection beat and says so.

### 3.22.2 Check-skipping closed (2026-09-08 evening, critic C-4; verified in crates/rec_aggregation/src/aggregation.rs:398-406)
The aggregate's public input is `statement_digest(public_keys.len(), pubkeys_hash(public_keys), message, epoch_hash, defer)`, so the signer count and the key set are bound: a guest cannot aggregate a smaller or different set against the verifier's public input. What the digest does not bind is whether each signature was checked, so: (a) every submission runs three negative vectors at fixed positions first, last and one verifier-random index; (b) any submission that clears the threshold runs the full one-bad-signature sweep, 900 runs each with exactly one invalid signature at index i, spread over the host's cores; a guest that skips any index is caught deterministically because that index's run must fail and does not. The sweep is ~1.4 s × 900 / cores; on 26 vCPU about one minute. (c) The perf-hunt numbers of 2026-09-08 afternoon are withdrawn by the builder (one stale binary measured at every commit); the metric decision rests on cycles being deterministic by construction, not on those numbers, and reachability is open until the corrected hunt (binary sha256 printed per run) reports.
- **Refinements (critic, 2026-09-08 evening):** (d) each negative vector flips a byte at a verifier-random offset inside the signature, not a fixed offset, so a guest that verifies only part of each signature is caught; (e) the verifier records the sha256 of the binary it measured with every measurement and refuses to measure when a non-empty diff was applied but the binary hash equals the reference binary's (the stale-binary failure of the perf hunt, moved to where it could pay out). Both live in `verifier/run.py` next to the frozen-path check.
